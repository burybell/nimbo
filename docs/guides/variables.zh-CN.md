# Nimbo 变量使用指南

[English](variables.en.md) · 简体中文

Nimbo 的变量可以复用地址、账号标识和其他请求数据。变量仅在本机解析；发送请求前，`{{变量名}}` 会替换为当前请求的最终有效值。

## 创建变量

- 环境变量：打开“环境”，选择当前环境后添加变量，适合开发、预发布、生产等全局配置。
- 集合变量：打开集合行的三点菜单并选择“变量”，适合一个 API 集合共享的地址或配置。
- 文件夹变量：打开文件夹行的三点菜单并选择“变量”，适合一个业务模块覆盖集合默认值。
- Runner 数据：运行集合时选择 CSV 或 JSON 文件，每一行都会成为当前迭代的临时变量。

每个变量包含启用状态、键、值、Secret 和说明。禁用、名称为空或最终值为空的变量不能满足请求中的引用。

## 优先级

同名变量按照离请求越近优先级越高的原则解析：

```text
Runner 数据行
  > 最近文件夹
  > 上级文件夹
  > 集合
  > 当前环境
```

例如环境和集合都定义了 `BASE_URL`，集合值会生效；请求位于还定义了 `BASE_URL` 的子文件夹中时，子文件夹值会继续覆盖集合值。Runner 数据只在对应迭代内生效，不会写回任何作用域。

## 在请求中使用

使用双花括号引用变量：

```text
{{BASE_URL}}/users/{{USER_ID}}
```

支持的位置包括：

- URL 和查询参数
- 请求标头
- Bearer、Basic 和 API Key 认证
- JSON、文本、表单和 Multipart 文本字段
- WebSocket 地址和文本消息
- SSE 地址、标头和认证
- Pre-request / Post-response Script 的环境读取
- Collection Runner 的请求执行

在支持的编辑器中输入 `{{` 会显示候选。使用方向键选择，按 Enter 或 Tab 补全。

## 查看最终值

- HTTP：打开请求的“设置”，向下查看“有效变量”。
- WebSocket / SSE：打开请求的“变量”页签。

每个变量会显示最终值、来源类型、来源名称和被覆盖的作用域。点击“编辑”可直接打开真正提供最终值的环境、集合或文件夹。

请求中引用但没有有效值的变量会提前显示在“缺少变量值”区域。点击“配置变量”会优先打开离请求最近的集合或文件夹；尚未保存到集合的请求会进入当前环境。

## Secret 与导出

Token、密码、Cookie 和其他凭据应标记为 Secret。有效变量列表还会自动遮罩常见的 Authorization、Password、Secret、Token、API Key、Access Key、Private Key、Credential 和 Cookie 键名。

普通 Nimbo 导出会递归清除环境、集合和文件夹中的 Secret 值。只有明确选择包含密钥的导出流程才会保留它们；不要将包含真实凭据的文件提交到 Git 或作为公开示例分发。

## 常见问题

### 变量存在但仍提示缺失

确认变量已启用、键名完全一致且值不为空。变量名区分大小写。

### 修改环境后没有使用预期值

查看“有效变量”的来源与覆盖链。同名集合或文件夹变量可能覆盖当前环境。

### Runner 中的变量为什么运行后消失

Runner 数据行是一次迭代的临时最高优先级输入，不会持久化。需要长期保存的值应写入环境、集合或文件夹。

### 脚本写入会修改集合变量吗

不会。`nimbo.environment.set` 和 JSONPath 提取只会写入明确选择的环境，不会隐式修改集合或文件夹变量。
